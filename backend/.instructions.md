# NeuroInfoGrinder Backend -- Project Rules

## applyTo
- `backend/**`

## Database

### PostgreSQL is the primary database
- Local PostgreSQL 15 runs on `localhost:5433`, user `postgres`, database `neuroinfogrinder`.
- H2 is no longer the development database. Do not start H2.
- Connection string: `jdbc:postgresql://localhost:5433/neuroinfogrinder`
- Flyway migrations run against PostgreSQL. All 16 existing migrations are PostgreSQL-compatible (H2 was in `MODE=PostgreSQL`).
- When adding new migrations, use native PostgreSQL syntax (no H2 compat hacks).
- After schema changes, verify with: `mvn flyway:info` and `mvn flyway:migrate`.

### Migration safety
- Never modify an existing Flyway migration file. Always add a new one.
- Migration filenames must follow `V{N}__description.sql` convention.
- Always test migrations against the local PostgreSQL before committing.

## Pipeline

### Date/time handling
- All date/time fields use `java.time.Instant` (UTC). No `LocalDateTime`, no `java.util.Date`.
- SQL columns use `TIMESTAMP WITH TIME ZONE`.
- API endpoints that accept date/time input must accept ISO-8601 format: `2026-06-08T14:30:00Z` or `2026-06-08T14:30:00+03:00`.
- Pipeline result filtering (`from`, `to` parameters) must accept full ISO-8601 date-time or date-only (`2026-06-08`) which is interpreted as start-of-day UTC.
- Frontend date/time pickers must send ISO-8601 strings, not epoch millis or locale-formatted strings.

### Pipeline stages
1. RULES -- keyword/regex/text checks (cheapest, no LLM)
2. SIGNAL_SCORING -- heuristic scoring (no LLM)
3. LLM CLASSIFIER -- expensive AI call
4. GUIDE_GENERATION -- most expensive AI call

### Pipeline conventions
- Signal threshold default: 0.05 (configured via `neuroinfogrinder.pipeline.signal-threshold`).
- Classifier threshold: 0.75.
- Auto-publish confidence: 0.85.
- Queue processor runs every 500ms, batch size 20.

## Code style

- Java 17, Spring Boot 3.4.x.
- MapStruct for entity/DTO mapping.
- Lombok for boilerplate reduction.
- Records for immutable DTOs where possible.
- JPA entities extend `BaseEntity` (provides `id`, `createdAt`, `updatedAt`).
- Repository methods: Spring Data JPA named queries and `@Query` only; no native queries unless performance-critical.
- All API endpoints under `/api/v1/`.
- OpenAPI/Swagger at `/v3/api-docs`.

## Testing

- Testcontainers with PostgreSQL module for integration tests.
- Do not use H2 for testing; use Testcontainers PostgreSQL.
- Unit tests do not need a database.
