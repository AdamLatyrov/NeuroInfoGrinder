# Как выбирать UI-стек для разработки

1. **Сначала выдели ядро и зафиксируй архитектуру**
   - Начни с CLI/консоли, чтобы проверить логику.
   - Затем вынеси бизнес-логику в отдельное ядро.

2. **Веб как быстрый старт (плюсы скорости и экосистемы)**
   - Большая библиотечная база и много готовых компонентов.
   - Практичный путь: взять проект в `Lovable`, адаптировать и довести до нужного вида.
   - Риск: возможные сложности с мостом/интерпретатором между UI и ядром при незрелом API.

3. **WPF: стабильный вариант, но с ручной доработкой UI**
   - Подходит как промежуточный рабочий путь.
   - Часто нужно рисовать/подгонять даже базовые контролы.

4. **Avalonia: перспективно для кроссплатформы**
   - Хороший выбор при желании уйти от WPF в будущем.
   - На практике может проявиться сильная зависимость от логики кэша.

5. **Рекомендованный порядок перехода**
   - Быстрый релиз на WPF.
   - После выстраивания стабильного API для ядра — миграция на Avalonia при необходимости.

# Краткий вывод
- Нужна скорость и готовые компоненты → веб (например через Lovable).
- Нужен быстрый Windows-референс → WPF.
- Нужна кроссплатформа в перспективе → плановая миграция на Avalonia.

# Как работает контекст в Cursor
- Контекст в Cursor считается **по чату**, не по всей подписке.
- Важен объём уже обработанных в этом чате данных и свободное место в текущем контексте.
- По мере заполнения контекста может произойти **compact** (сжатие/обновление истории).

## Что делать
1. Планируйте работу по отдельным чатам для разных задач.
