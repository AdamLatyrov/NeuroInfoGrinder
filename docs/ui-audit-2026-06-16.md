## Top overloaded areas

1. Конвейер: карточки результата сообщения показывают всё сразу.
2. Детальная страница гайда: metadata, raw, trace и source messages конкурируют с контентом.
3. Промпты: редактирование, тесты и метрики смешаны.
4. Правила/классификаторы: порядок, статусы, условия и actions в одном слое.
5. Dashboard: много KPI без явной связи с действиями.
6. Группы: синхронизация/чат/темы/статистика смешаны.
7. AI-провайдеры: provider setup и health-check в одном блоке.
8. Настройки: системные лимиты рядом с пользовательскими режимами.
9. Сигналы: ручные pipeline-шаги требуют аккуратной progressive disclosure.
10. Гайды: таблица всё ещё плотная, но основные ошибки и действия теперь вынесены.

## Top confusing buttons/items

1. Dashboard refresh: исправлено, теперь refetch.
2. Dashboard export: убрано, endpoint/action не было.
3. Dashboard "Добавить": исправлено, пункты ведут на страницы.
4. Command palette redirect links: исправлено.
5. Guides refresh: исправлено, refetch + loading.
6. Guides error retry/delete: retry подключён к реальному endpoint; delete отключён, потому что backend выполняет hard delete без архивации.
7. Guides status actions: исправлено для approve/publish/send/retry/delete.
8. Signals embeddings/micro/macro: исправлено, есть result/error.
9. Signals backfill: disabled с пояснением, backend endpoint не найден.
10. Pipeline retry labels: требует перевода и более понятного feedback.

## Simplification proposals

- Ввести общий `OperationNotice`/toast для всех страниц вместо локальных строк результата.
- Ввести `IconActionButton` с обязательными `title` и `aria-label`.
- Разделить пользовательский и технический режимы: trace/raw/tokens/provider id показывать в "Технические детали".
- Для таблиц держать 5-7 видимых колонок, остальное в detail drawer.
- Для массовых операций всегда показывать counts: запрошено, успешно, пропущено, ошибок.
- Для функций без backend endpoint использовать disabled-state с пояснением, не активные заглушки.
